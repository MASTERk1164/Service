재작성
C# 및 Windows Forms로 전체 구현을 새로 작성했습니다.
소스 외에 사전 빌드 EXE, 설치 프로그램, 외부 DLL을 새 패키지에 넣지 않았습니다.
Build.cmd는 PC의 Microsoft .NET Framework 컴파일러를 명시적으로 호출합니다.
Start.cmd는 빌드가 성공한 경우에만 같은 폴더의 ScheduledText.exe를 실행합니다.
난독화, 패킹, 숨김 실행, 다운로드, 보안 우회 옵션을 추가하지 않았습니다.
로컬 빌드 방식은 백신 탐지를 피하거나 무해함을 증명하는 수단이 아닙니다.
사용자가 실행 코드를 확인할 수 있고 외부 빌드 도구 의존을 줄이기 위한 방식입니다.

새 코드의 OS 호출 범위
user32.dll: RegisterHotKey, UnregisterHotKey, GetCursorPos, WindowFromPoint,
GetAncestor, GetForegroundWindow, IsWindow, IsWindowVisible, IsIconic,
SetCursorPos, SendInput, SetForegroundWindow, ShowWindowAsync, ClientToScreen, ScreenToClient.
kernel32.dll: GetTickCount64.
F8/Esc 등록은 지정 단축키 알림만 받습니다. 키보드 후크/입력 감시는 없습니다.
마우스 클릭과 문자 입력은 사용자 지정 좌표·문구를 SendInput으로 전송합니다.
문구·좌표는 메모리에서만 사용하며, 앱은 파일·레지스트리·클립보드에 저장하지 않습니다.
빌드 스크립트는 폴더에 ScheduledText.exe를 생성합니다. 앱의 파일 저장과 구별됩니다.

검증
Debian 배포 저장소에서 받은 Mono C# 컴파일러로 C# 5 문법, x64,
경고를 오류로 취급하는 설정으로 전체 소스를 컴파일했습니다.
검증용 EXE는 패키지에 포함하지 않았습니다.
Schedule.cs 예약 코드에 대한 실행 테스트와 x64 SendInput 구조 검사 총 16개 통과:
- 1분 첫 실행 및 5분 간격의 6분/11분/16분 예약

- 반복 간격 초과 시 중단
- 0초 및 범위 초과 인자 거부
- Windows x64 INPUT/union/KEYBDINPUT 크기 및 정렬
Windows GUI 실제 실행, Microsoft csc 실기 빌드, Defender/상용 백신 검사,
SmartScreen 평판 확인, 코드 서명은 수행하지 못했습니다.
'바이러스 없음', '오탐', '경고 해결'로 판단한 결과가 아닙니다.

기존 경고 파일은 격리 상태를 유지하세요. 새 파일도 경고가 발생하면 중단하세요.
